# 安全架构

## 默认与权限

所有执行开关默认关闭；能力未知等同不支持。初版为 host 可测试决策核心、模块生命周期骨架与只读/演示 UI。禁止用配置字符串拼装任意 shell 命令，禁止扫描后批量冻结所有后台应用。

## 应用休眠

`observed → eligible → freeze_pending → frozen → thaw_pending → observed`；任何失配、未知保护信息、超时或解冻失败进入降级并禁止新冻结。目标身份必须包含 package、UID、PID、/proc starttime 和 boot identity。共享 UID、多用户、isolated UID、系统应用默认拒绝。

必须知晓并排除前台/可见、前台服务、音频播放/录音、通话、输入法、无障碍、VPN、设备管理员/关键系统服务，以及 Binder/文件锁关联风险。保护信号失效时优先解冻自己的目标。

不使用 SIGSTOP、force-stop、禁用组件、杀后台作为真实冻结替代。Android 适配器未验证前没有真实冻结执行能力。以后优先框架协作，避免绕过 ActivityManager 的解冻路径。

## 性能

以屏幕、交互、音频、热状态选择观察场景；温度未知不增强性能。写入执行器必须按机型审计路径/合法值，读原值，先持久化事务，再写入并读回。部分失败倒序恢复；恢复只改仍由自己持有的值，避免覆盖系统/其他调度器的新值；未恢复条目保留证据并阻止新事务。

## 启动与恢复

不设置 post-fs-data 阻塞；晚期 service 运行且有有界等待。每个 boot ID 只计数一次；同一启动重复调用幂等。仅本模块健康检查失败累计；健康运行才清零。连续失败停用自身，留下原因；禁止自行重启循环。停用后不自动重新启用。

恢复不保证 bootloader、分区/内核损坏、数据丢失或别的模块引起的故障可救。独立于本模块脚本能否执行的恢复手段是 Root 管理器安全模式和手动移除本模块。

## 参考模型与设备实现的界线

Python 核心通过注入的 mock adapter 验证逻辑，不包含真实 freeze/sysfs 执行器。身份的前后读取不能消除 TOCTOU；未来 backend 必须提供 pidfd/等价原子身份保护。原值比较也不是原子 CAS；没有排他控制/兼容策略时禁止和系统或其他模块争写。

BootGuard 的 JSON/fsync/锁测试是 host 参考，尚未连接模块 disable 标记。跨启动 pending 表示“上一次本模块健康握手未完成”，不证明故障由本模块引起；保守停用可以接受，但不能标成精确故障归因。真实健康条件不能仅用 sys.boot_completed，必须验证恢复记录、协调器、自检和宽限期。没有安装、开机故障注入或实机省电收益测试证据。

## 第二阶段：只读Android桥接

新增C++ probe与默认关闭的Root WebUI只读协议，源码与host验证先行，不连带获得任何VM/实体设备Root授权。设备端只读探针不是冻结执行器；Binder节点/pidfd/freezer文件存在都不能把freeze_ready置为true。实际AMS夹具实验另见VM-VALIDATION。
